# 20. 業務ルール

棚卸商品管理機能の業務上の振る舞いを定義する。

## 棚卸ステータス（`inventoryOn`）の意味

棚卸し作業時に「棚卸対象とするか」を表すフラグ。

| 値 | 表示 | 意味 |
|---|---|---|
| `true` | 表示 | 棚卸し作業時にカウント対象。棚卸入力画面に表示される |
| `false` | 非表示 | 棚卸し作業時にカウント対象外。商品マスタからは消えないが棚卸入力画面に表示されない |

**「非表示」は削除ではない。** 一時的に棚卸対象から外したい商品(季節商品/取扱停止中の商品など)を、マスタを残したまま除外する用途を想定。

## 登録経路（`route`）の5分類とソース

| 経路 | データソース | 主な特徴 |
|---|---|---|
| インフォマート連携 | インフォマート受発注API | 自動同期。商品コードあり。最も件数が多い(45%想定) |
| 納品書書き起こし | 納品書(紙/PDF/FAX)からの書き起こし | OCR + 手入力。FAX発注も統合済み。商品コードは空が多い(53%想定) |
| 発注アプリ連携 | アスクル等の発注アプリ | 雑貨・備品が中心(2%想定) |
| 自社加工品 | 本機能の新規追加画面 | 店舗で加工した商品。発注先なし、単価なしで開始(0.1%想定) |

※ 過去仕様では「FAX発注」を独立した5分類目として扱っていたが、運用上「納品書書き起こし」と業務フローが同一(書き起こし作業)のため統合された。現行は実質4分類。

## 登録経路ごとのマスタ更新ルール

各経路でマスタの新規作成・更新方法が異なる:

- **インフォマート連携**: 連携先マスタの変更が自動反映。本機能では編集不可項目を変更できない
- **納品書書き起こし**: 書き起こし業務側で再登録/修正
- **発注アプリ連携**: 発注アプリ側でマスタ更新
- **自社加工品**: 本機能の新規追加画面 / 編集画面で更新

## 棚卸推奨単価（`price`）の出所

「直近の棚卸し履歴」から取得する単価で、棚卸入力時の初期値候補として使う。
- 未棚卸の商品(履歴なし) → `price = 0`、一覧では `-` 表示
- 履歴あり → 最新の `unitPrice` を採用

データ画面の「棚卸し参考データ」セクションでは、取得元の棚卸実施日を補足表示する(`直近の棚卸データ（YYYY年M月D日）での単価です。`)。

## 自社加工品の運用

- 新規追加画面から登録すると `route = 'in-house'` / `supplier = '-'` / `price = 0` で作成される
- 一覧画面で「アクション > 編集」から棚卸ステータス・単位・税区分を変更できる
- 商品名・商品コードを後から変更したい場合は、いったん削除して再登録する運用
  - ※ 削除動作の本実装挙動は未定 → [90. 未決事項](./90_open_questions.md)

## ステータス変更の操作経路

棚卸ステータスは以下3つの経路で変更可能:
1. 編集画面のトグルスイッチ → 単件更新
2. 一覧画面のチェックボックス選択 + 「一括：表示にする」「一括：非表示にする」 → 複数件一括更新
3. (将来) 一覧テーブル行内のクイックトグル → 未実装

## デザインルール

- 一覧画面のステータス表現は **プレーン色付きテキスト** (緑=表示 / グレー=非表示)
- データ画面・編集画面では登録経路を **色付きバッジ** で視覚化(一覧では列削除済みのため詳細画面側で経路の視覚的区別を担保)
- 必須項目ラベルには赤字で `（必須）`、任意項目には灰字で `（任意）` を付ける
