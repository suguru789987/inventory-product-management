# 20. 業務ルール

棚卸商品管理機能の業務上の振る舞いを定義する。

## 棚卸ステータス（`inventoryOn`）の意味

棚卸し作業時に「棚卸対象とするか」を表すフラグ。

| 値 | 表示 | 意味 |
|---|---|---|
| `true` | 表示 | 棚卸し作業時にカウント対象。棚卸入力画面に表示される |
| `false` | 非表示 | 棚卸し作業時にカウント対象外。商品マスタからは消えないが棚卸入力画面に表示されない |

**「非表示」は削除ではない。** 一時的に棚卸対象から外したい商品(季節商品/取扱停止中の商品など)を、マスタを残したまま除外する用途を想定。

## 棚卸属性 / 発注属性の独立と移行方針

商品は「棚卸対象か(`inventoryOn`)」と「発注対象か(`orderOn`)」の2つの独立属性を持つ（→ [10. データモデル](./10_data_model.md)）。
仕入商品（インフォマート連携・納品書書き起こし）は「仕入れた商品を有姿のまま棚卸する」のが基本で、本来は **発注OFF / 棚卸ON** が望ましい。

### 既存データの移行（採用＝案2 / UI先行・ミニマム）

| 案 | 内容 | ボリューム | 採否 |
|---|---|---|---|
| 案1 | 既存商品も含め一括で「発注OFF / 棚卸ON」に整える | 一括更新あり・約71万件(インフォマート39万＝45% / 書き起こし32万＝37%) | 後追い（バックエンド別タスク） |
| 案2 | **既存データは現状維持**（発注OFF / 棚卸OFFのまま）、本画面でユーザーが手動で棚卸ONにできるUIを提供 | 一括更新なし | **採用（今回スコープ）** |

採用理由（PO判断）: クリティカルでないため、まずはUI変更のミニマムで対応。一括更新（案1）は負荷を分けて後追いでリリース準備する。
→ **本画面の一括「棚卸対象に含める」操作が、既存仕入商品を棚卸対象に取り込む主要動線**となる。

## 費目（`category`）の登録ルール

- 費目セレクタの選択肢は**店舗が費用設定で設定した「変動費目」を引いてくる**（`monthly_cost_items`）。仕入・食材は変動費なので、変動費予算へ実績を積むための単一マスタ参照とする。
- **自社加工品**は顧客が作成するものなので、**登録時に変動費目から手動選択**する（新規追加画面で必須・`is_ai_generated=false`）。
- 当初検討された「商品名からのAI推定（フォールバック）」は自社加工品では採用しない。顧客の明示選択を正とする。
- **連携・書き起こし・発注システム商品**の費目はAIが自動付与（`is_ai_generated=true`）。**編集画面では費目を編集不可（参照のみ）**とする。
  - 理由: 連携商品の非ステータス項目は日次自動更新されるため、手編集すると上書きされる／整合が崩れる。本番の「連携商品は棚卸ステータスのみ編集可」とも整合。
  - 費目編集を許すのは**自社加工品のみ**（`route='in-house'`）。
- 保存先は `shop_item_expenditure_types.expenditure_type`。`expenditure_type` が変動費目を参照するか別enumかは要確認（OQ-11）。

## 登録経路（`route`）の5分類とソース

| 経路 | データソース | 主な特徴 |
|---|---|---|
| インフォマート連携 | インフォマート受発注API | 自動同期。商品コードあり。最も件数が多い(45%想定) |
| 納品書書き起こし | 納品書(紙/PDF/FAX)からの書き起こし | OCR + 手入力。FAX発注も統合済み。商品コードは空が多い(53%想定) |
| 発注アプリ連携 | アスクル等の発注アプリ | 雑貨・備品が中心(2%想定) |
| 自社加工品 | 本機能の新規追加画面 | 店舗で加工した商品。発注先なし、単価なしで開始(0.1%想定) |

※ 過去仕様では「FAX発注」を独立した5分類目として扱っていたが、運用上「納品書書き起こし」と業務フローが同一(書き起こし作業)のため統合された。現行は実質4分類。

## 登録経路ごとのマスタ更新ルール

各経路でマスタの新規作成・更新方法が異なる:

- **インフォマート連携**: 連携先マスタの変更が自動反映。本機能では編集不可項目を変更できない
- **納品書書き起こし**: 書き起こし業務側で再登録/修正
- **発注アプリ連携**: 発注アプリ側でマスタ更新
- **自社加工品**: 本機能の新規追加画面 / 編集画面で更新

## 棚卸推奨単価（`price`）の出所

「直近の棚卸し履歴」から取得する単価で、棚卸入力時の初期値候補として使う。
- 未棚卸の商品(履歴なし) → `price = 0`、一覧では `-` 表示
- 履歴あり → 最新の `unitPrice` を採用

データ画面の「棚卸し参考データ」セクションでは、取得元の棚卸実施日を補足表示する(`直近の棚卸データ（YYYY年M月D日）での単価です。`)。

## 自社加工品の運用

- 新規追加画面から登録すると `route = 'in-house'` / `supplier = '（自社加工品）'` / `inventoryOn = true` / `orderOn = false` / `price = 0` で作成される
- 費目は登録フォームで必須選択（中間加工品も含め顧客が費目を確定させる）
- 一覧画面で「アクション > 編集」から棚卸ステータス・費目・単位・税区分を変更できる
- 商品名・商品コードを後から変更したい場合は、いったん削除して再登録する運用
  - ※ 削除動作の本実装挙動は未定 → [90. 未決事項](./90_open_questions.md)

## ステータス変更の操作経路

棚卸ステータスは以下3つの経路で変更可能:
1. 編集画面のトグルスイッチ → 単件更新
2. 一覧画面のチェックボックス選択 + 「一括：棚卸対象に含める」「一括：棚卸対象から外す」 → 複数件一括更新（既存仕入商品の棚卸取り込み動線）
3. (将来) 一覧テーブル行内のクイックトグル → 未実装

## デザインルール

- 一覧画面のステータス表現は **プレーン色付きテキスト** (緑=表示 / グレー=非表示)
- データ画面・編集画面では登録経路を **色付きバッジ** で視覚化(一覧では列削除済みのため詳細画面側で経路の視覚的区別を担保)
- 必須項目ラベルには赤字で `（必須）`、任意項目には灰字で `（任意）` を付ける
