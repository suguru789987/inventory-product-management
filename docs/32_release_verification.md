# 32. リリース検証プラン（自社加工品の新規登録 / 費目3択化）

本リリースの検証計画。**「登録に必要なものが過不足なく登録できる」** ことと、
**費目が固定3区分（食材 / 飲料 / 資材）に統一されている** ことを確認する。

> 役割分担：
> - **本書 (32)** … 今回リリース範囲の検証（モック操作 + ステージング実データ）。
> - [30. 検証計画](./30_verification.md) … MUGEN実データ突合 / 71万件負荷（このリリースのクリティカルパス外）。
> - [31. モック操作確認](./31_mock_verification.md) … 属性分離・取り込みのモック確認（既存）。

### 登録動線の実機テスト（2026-05-21・STEP1〜3実施）

**追加で見つかった指摘:**
- 🟡 費目の必須バリデーションメッセージが英語混在（「**Expenditure type**を選択してください」）。他項目は日本語のため未ローカライズ。要修正（軽微）。
- 🟡 新規登録分の**発注先が「自社加工品」表示**（既存品は工場名）。仕様意図の確認要。

**残り（STEP4・5 未消化）:** STEP4=編集で費目/単位/税区分を変更・保存できるか、STEP5=棚卸入力画面への反映。この2点が通れば本リリースのステージング検証クリア。

## リリース範囲（検証対象）

| # | 範囲 | 内容 |
|---|---|---|
| R-1 | **自社加工品の新規登録** | 新規追加画面から `route='in-house'` の商品を登録できる |
| R-2 | **登録必須項目の網羅** | 登録に必要な項目が過不足なく入力・保存できる |
| R-3 | **費目の固定3択化** | 費目セレクタが「食材 / 飲料 / 資材」の3つのみ。旧ラベル（食材費/酒類費/ドリンク費/消耗品費/その他変動費）が一切出ない |

### 登録に必要な項目（自社加工品）
| 項目 | 必須 | 値 / 制約 |
|---|---|---|
| 商品名 | ◯ | 自由入力 |
| 商品コード | － | 任意 |
| 棚卸ステータス | ◯ | デフォルト「表示」 |
| 費目 | ◯ | **食材 / 飲料 / 資材** の3択 |
| 単位 | ◯ | 個/パック/本/箱/樽/kg/g/L/ml |
| 税区分 | ◯ | 外税(標準/軽減)/内税(標準/軽減)/非課税 |
| 発注対象 | 自動 | 常に `orderOn=false`（自社加工品は発注対象外） |

## B. ステージング検証（実データ）

実データを載せたステージング環境で、登録がDBまで正しく永続化されるかを確認する。

| ID | 観点 | 手順 | 期待結果 |
|---|---|---|---|
| RVS-01 | 自社加工品の永続化 | ステージUIで自社加工品を新規登録 | `shop_items` にレコード生成。`inventory_enabled=true` / `orderable=false` / `is_ai_generated=false` |
| RVS-02 | 費目の保存とenum対応 | RVS-01の費目（食材/飲料/資材）を保存 | `shop_item_expenditure_types.expenditure_type` に固定3区分が正しくマップされ保存される（セレクタ側は食材/飲料/資材で動作確認済み＝OQ-11の保存先enum対応のみ要確定） |
| RVS-03 | 登録商品の下流反映 | 登録後、一覧・棚卸入力画面を開く | 登録した自社加工品が棚卸対象として表示・カウントされる |
| RVS-04 | サーバー側バリデーション | 必須項目を欠いたリクエストをAPIへ送る | サーバー側でも弾かれる（クライアントのバリデーションに依存しない） |
| RVS-05 | 既存商品の費目表示 | 既存の連携・書き起こし商品のデータを開く | 費目が新3区分（食材/飲料/資材）で表示される（移行/マッピング済み） |
| RVS-06 | 費目補足文言の修正 | 新規追加・編集画面の費目欄補足文言 | 「仕入商品の品目区分（食材／飲料／資材）から選択します」に修正（現状は旧文言「費用設定の変動費目から選択します」＝**要修正**） |
| RVS-07 | 自社加工品の編集可否 | 自社加工品の編集画面で費目/単位/税区分を変更し更新 | 自社加工品はこれら3項目が**編集可能**（実機で灰色表示のため要目視確認） |
| RVS-08 | 自社加工品の発注先 | 自社加工品のデータ/編集で発注先を確認 | セントラルキッチン/工場名（例:群馬デスコ桐生市本社工場）が入る。モックの想定（発注先=「-」）と実態の差異を仕様に反映するか判断 |

> ⚠️ RVS-02 の `expenditure_type`(int) のenum定義（コード→ラベル）と固定3区分の対応はエンジニア提示待ち（[OQ-11](./90_open_questions.md)）。
> セレクタ自体は食材/飲料/資材で動作確認済み（2026-05-21）。enum定義は本番アプリコード（rakmy_server）にある想定 → 本番には触れず提示を依頼する。
> **RVS-06 が本リリースで直すべき唯一の確定不具合**（費目欄の補足文言が旧仕様）。

## C. 合否基準

- **モック:** A-1〜A-3 がすべて期待通り。特に RV-01/RV-02（費目3択・旧ラベル不在）と RV-05〜RV-11（必須網羅・正常登録）が PASS。

- ❌ が出た場合、モック層は `index.html` の該当箇所、ステージング層はAPI/保存ロジックを起点に切り分ける。
